# f1_pool_cleaning 开发与验收文档

日期：2026-10-24  
版本：v0.2-stage2
状态：阶段 1 正常流程验证通过；阶段 2 软件实现已加入，实船异常场景和重复验收证据待补齐，不代表四边自动换边已经实现

## 1. 目标与当前边界

目标是让船在预先建立的池体地图中完成以下任务：

1. 通过 RViz2 标定初始位置和船头方向，完成固定地图定位。
2. 将池边拆成多个长直边，复用同一套沿边控制清洗。
3. 矩形池自动清洗四条边的主要区域，角部保留明确的安全留白。
4. 将同一任务模型扩展到凸多边形，再处理有凹角的多边形。

当前 `f1_pool_cleaning` 已完成两个旧清洗包的合并，并保留：

- 左墙线提取、墙线关联、短暂丢墙恢复和墙线可视化；
- 墙距 32–36 cm 的第五路侧推控制，目标中心值 34 cm；
- 墙角 ±10° 刷盘门控和 ±3° 连续主电机纠偏；
- 固定地图 `map → base_link` 位姿输入及前墙停车判断；
- 任务租约、遥控接管、数据过期停机和显式 start/cancel 流程。

阶段 2 已加入矩形边界、地图边选择、目标墙关联、靠墙/入口调整、边端点停车和左侧滚刷接触区间记录；自动离墙、转角、换边和四边任务编排仍未完成。

阶段 1 正常流程验证通过：新增 `pool_localization_manager`，通过 `/initialpose` 或 `/pool_cleaning/set_initial_pose` 管理 Cartographer 纯定位轨迹；新增 `LOCALIZATION_CHECK`、`LOCALIZATION_READY` 和锁存的 `PAUSED` 门控；控制器在定位未就绪、定位状态过期或定位退化时拒绝启动并关闭输出。异常场景和重复验收证据待补齐，当前不能称为“全池清洗完成”。

## 2. 总体架构

```text
冻结地图 pbstream / 栅格地图
             │
             ▼
       定位管理节点
 RViz2 初始位姿 → Cartographer → map → base_link
             │
             ├──────────────┐
             ▼              ▼
      边任务管理器       墙线感知
  当前边/进度/转移阶段   实时墙距/墙角/障碍
             │              │
             └──────┬───────┘
                    ▼
             直边控制器
                    │
                    ▼
              f1_nano_bridge
                    │
                    ▼
                 F103/Nano
```

模块职责必须保持清晰：

| 模块 | 职责 |
|---|---|
| 地图与定位 | 提供稳定、带时间戳的 `map → base_link` 位姿；不直接发执行器指令 |
| 墙线感知 | 从雷达提取当前目标墙，输出墙距、切线角、墙段支持长度和障碍证据 |
| 边任务管理器 | 选择边、判断沿边进度、安排转移和下一条边，不实现电机混控 |
| 直边控制器 | 根据实时墙线维持墙距、航向和刷盘输出 |
| 转移控制器 | 在安全包络内离墙、转向、靠近下一边；使用反馈判断完成 |
| 硬件桥 | 租约、命令期限、方向编码、串口和硬件停止屏障 |

地图位姿负责全局位置和边进度，墙线负责近墙控制。二者的时间戳、坐标系和新鲜度必须分别检查，不能把任一反馈的缺失当作另一反馈有效。

## 3. 任务和数据模型

### 3.1 池边模型

后续配置不再写死“左墙”或“长边”，统一使用有序边段：

```yaml
pool:
  frame: map
  boundary:
    - [x0, y0]
    - [x1, y1]
    - [x2, y2]
    - [x3, y3]
  boundary_order: clockwise
  corner_exclusion_m: 0.30
  wall_target_m: 0.34
  # Boat-centre distance to the front wall at which this edge stops.
  endpoint_margin_m: 0.50
```

实现时每条边应展开为内部结构 `EdgeSegment`，至少包含：

- `id`、起点、终点和单位切向量；
- 墙法向和船应行驶的方向；
- 清洗有效区间、入口和退出位置；
- 目标墙距、终点净空和允许误差；
- 下一条边及其转移方案；
- 计划长度、已清洗区间和未覆盖区间。

阶段 2 只允许配置的池坐标 `+y` 左侧边作为可执行边，使墙始终位于船体左侧，继续复用当前左墙控制。若请求其他边或方向会让墙位于右侧，必须拒绝启动；不能通过符号反转或改写边身份模拟右侧刷墙。其他边应作为后续转移能力实现。

### 3.2 任务状态

当前实现和后续阶段共用以下状态方向；阶段 2 的 `EDGE_SELECT` 是启动门控内部步骤，不单独发运动输出：

```text
IDLE
  → LOCALIZATION_CHECK
  → EDGE_SELECT
  → APPROACH_WALL
  → APPROACH_EDGE
  → FOLLOW / CORRECT_HEADING / WAIT_WALL
  → EDGE_STOP
  → VERIFY_STOP
  → MOVE_INWARD
  → TURN_TO_NEXT_EDGE
  → APPROACH_NEXT_EDGE
  → FOLLOW_EDGE
  → COMPLETE
```

任意运动状态都可以进入 `PAUSED` 或 `ABORTED`。出现以下情况时必须关闭所有输出：定位过期或跳变、墙线过期、障碍未知、转移超时、租约失效、RC 接管、时钟故障、执行器命令过期。

`PAUSED` 不因数据恢复自动继续。需要操作者检查原因、执行 cancel，再重新 start；重新 start 必须重新确认定位、目标边和墙线。

## 4. 开发与验收阶段

### 阶段 0：合并后基线冻结

**目的**：确保后续开发只在一份有效控制代码上进行。

**实现内容**：

- 只保留 `f1_pool_cleaning`，旧 `f1_rectangle_cleaning` 和 `f1_wall_cleaning` 不再被 colcon 发现；
- 感知参数和单边控制参数分开；
- 保持 `/pool_cleaning/*` 话题、服务和 `pool_*` 启动入口；
- 保留墙线丢失、角度符号、前墙停车、租约和超时回归测试。

**验收门槛**：

- 四个项目包构建成功；
- `f1_pool_cleaning` 现有单元和 ROS 测试全部通过；
- `pool_demo` 可运行；
- 默认 `output_enabled=false`，不能产生硬件输出；
- 旧包不出现在 `colcon list` 和安装索引；
- 迁移说明可以在 PC 和 Nano 上清理旧源码、build、install 目录。

阶段 0 已完成。后续阶段不应重新引入旧单边控制器或第二份电机输出逻辑。

### 阶段 1：定位与 RViz2 初始位姿

**目的**：船下水后位于大致区域，由操作者在 RViz2 标定精确初始位姿，定位节点再输出可靠的 `map → base_link`。

**实现内容**：

1. 启动冻结地图、雷达静态 TF 和定位节点，但不启动运动任务。
2. RViz2 Fixed Frame 设置为 `map`，显示地图、LaserScan、TF 和船体位姿。
3. `2D Pose Estimate` 发布初始位置和朝向；定位管理节点接收并转换为 Cartographer `start_trajectory` 的初始位姿。
4. 初始位姿提交期间保持任务 `IDLE`，禁止申请运动租约。
5. 定位管理节点检查轨迹状态、位姿新鲜度、扫描与地图的重合程度和跳变。
6. 达到稳定条件后发布 `LOCALIZATION_READY`，否则保持 `LOCALIZATION_CHECK`。

当前 `pool_localization.launch.py` 会加载冻结 pbstream、发布雷达静态 TF、启动栅格地图节点发布 `/map`，并启动定位管理器；管理器把 RViz 初始位姿转换为 `StartTrajectory` 请求，查询轨迹状态，并在位姿、扫描、地图边界和扫描端点与 `/map` 占用栅格的重合连续稳定后发布 `LOCALIZATION_READY`。不能把“轨迹创建成功”当成定位正确。

**建议接口**：

- 输入：`/initialpose`，`geometry_msgs/PoseWithCovarianceStamped`；
- 输出：`map → base_link` TF、定位状态和诊断；
- 服务：`/pool_cleaning/set_initial_pose`（`f1_interfaces/SetInitialPose`）、`/pool_cleaning/relocalize`（`std_srvs/Trigger`）；
- 任务门控：没有 `LOCALIZATION_READY` 时 `/pool_cleaning/start` 必须拒绝。

**验收方法**：

- 在地图中至少选择左上、右上、左下、右下四个不同初始区域，各重复 3 次；
- RViz2 标定方向后，TF 的位置和朝向稳定更新；
- 人为给出错误朝向或地图外位置时，任务保持 IDLE 并报告原因；
- 重新定位时不会保留旧任务租约或旧墙线关联；
- 定位节点重启、雷达断流、TF 过期、位姿跳变都不会产生运动输出；
- 保存 RViz 配置、初始位姿、定位状态日志和对应 rosbag。

**软件通过条件**：连续测试覆盖初始位姿校验、轨迹生命周期、TF/扫描过期、地图外位姿、扫描重合不足、位姿跳变和控制器启动门控，默认 `output_enabled=false`。**现场通过条件**仍为四个区域各 3 次完整操作，且保存 RViz 配置、初始位姿、定位状态日志和对应 rosbag；现场通过前不得进入实船自动换边开发。

**当前记录**：阶段 1 正常流程验证通过；异常场景和重复验收证据待补齐。

### 阶段 2：通用直边控制

**目的**：把当前“左墙单边控制”改造成使用统一 `EdgeSegment` 数据的直边任务，控制算法只保留一份。阶段 2 使用配置的目标边（当前默认 `edge_0`），要求墙位于 `base_link +y`，让单个左侧滚刷稳定刷墙，不包含自动换边。

**实现内容**：

- 用地图位姿将船投影到当前边的切向和法向坐标；
- 根据边方向判断沿程进度、入口和出口；
- 将目标边身份传给墙线感知，防止丢墙后误认相邻墙；
- 继续使用墙线实时控制墙距和夹角；
- 船体按长 0.50 m、宽 0.45 m 的矩形包络建模；左侧唯一滚刷的稳定中心墙距为 0.34 m，允许区间为 0.32–0.36 m；
- 初始只需在默认目标边附近粗略放置，Cartographer 稳定后将该地图边转换到机器人坐标，先关闭滚刷靠墙并纠正航向，再沿边调整到入口；
- 将终点判断改为当前边终点与船中心的沿程距离，船中心距前方墙约 0.50 m 时停止；
- 当前边进入 `EDGE_STOP` 后关闭刷盘、主电机和第五路输出；
- 记录左侧滚刷接触中心线的有效清洗区间，不把停车、丢墙、暂停或转移区间计入覆盖。

阶段 2 只允许墙位于机器人 `base_link +y` 的 canonical 边作为可执行边，使墙始终位于船体左侧，继续复用当前左墙控制。若请求的边或方向会让墙位于右侧，必须拒绝启动；不能通过符号反转或改写边身份模拟右侧刷墙。

**验收方法**：

- 用同一控制器分别执行矩形四条边，人工只将船粗略放在对应边附近并调整船头方向，使墙位于机器人左侧；
- 每条边的反向请求必须拒绝，不能通过符号反转模拟右侧刷墙；
- 每条边至少执行 3 次粗放置—定位—靠墙—入口调整—直边跟踪流程；
- 检查墙距、墙角符号、边进度和端点停车；
- 端点前后故意加入定位和墙线扰动，确认不会越过安全净空；
- 检查墙线丢失后不会自动切换到相邻墙；
- 用合成反馈、rosbag 回放和 ROS 联调三层测试覆盖相同状态。

**通过条件**：矩形四条边都能使用同一套控制器完成“地图定位—左侧边确认—靠墙调整—入口对齐—直边跟踪—安全停车”；右侧墙线、反向刷墙和自动换边不属于本阶段能力。

### 阶段 3：一次自动换边

**目的**：完成一条边到相邻边的可验证自动转移，作为四边串联前的最小闭环。

**标准流程**：

1. `FOLLOW_EDGE` 到达出口区，关刷并停止推进。
2. `VERIFY_STOP` 使用连续位姿变化或速度估计确认船体已停止；下发 STOP 不等于物理停稳。
3. `MOVE_INWARD` 向池内移动到转角所需的安全距离。
4. 再次停止并确认雷达、地图和转移区域有效。
5. `TURN_TO_NEXT_EDGE` 按目标边方向转动；使用连续展开角度和局部位姿判断完成，不能用固定秒数代替角度反馈。
6. `APPROACH_NEXT_EDGE` 接近下一边，重新建立目标墙关联。
7. 目标墙距、墙角和位置稳定后进入下一次 `FOLLOW_EDGE`。

转移过程必须使用完整船体、刷座和刷头的扫掠包络。盲区、未知回波或定位退化不能当成自由空间。当前单边控制最多涉及小角度诊断，不能直接复用于 90° 或 180° 转向。

**验收方法**：

- 先关闭刷盘，在开阔水域做离墙、停止、转向和靠墙的单动作标定；
- 测量每个动作的位移、角度、余转、停止时间和漂移，更新配置；
- 在仿真/回放中验证每个状态的超时、障碍和丢定位分支；
- 无障碍条件下完成一次长边到相邻短边的转移；
- 在转移中遮挡雷达或中断定位，确认立即停车且不自动恢复；
- 保留起点、转移轨迹、终点和停止原因。

**通过条件**：同一转移路线连续 5 次完成，未碰撞、未越界、未误认墙，转移时间和漂移均处于实测上限内。通过前不得串联四边。

### 阶段 4：矩形四边与覆盖率

**目的**：将四条边和三个/四个转移串成完整矩形任务，并报告实际覆盖区域。

**实现内容**：

- 从矩形配置生成 4 个 `EdgeSegment`；
- 为每条边单独计算入口、出口、端部留白和允许清洗区间；
- 根据池宽、船体包络、刷头覆盖和停止漂移生成转移区域；
- 维护 `current_edge_id`、`completed_edges`、`cleaned_intervals` 和 `uncovered_intervals`；
- 任务结束时输出已清洗边、计划长度、有效长度、暂停区间和未覆盖原因；
- 角部不要求刷到，但角部留白必须可配置、可显示、可审计。

当前地图估计约为 2.883 m × 1.520 m。每条边都按船中心到其前方墙约 50 cm 的规则独立计算可清洗长度；短边不能用长边的沿程长度或船体前缘距离替代。开始任务前应显示预计覆盖率，若某条短边可清洗长度不足，任务应报告而不是伪造“全池完成”。

**验收方法**：

- 先使用 `output_enabled=false` 完成全流程回放和预览；
- 再关闭刷盘进行实船四边转移试验；
- 最后在确认方向、停车、转移和刷头接触后开启刷盘；
- 四边各至少重复 3 次，记录每条边起止点和未覆盖区间；
- 对矩形整体执行一次完整任务，验证中途暂停、重新定位、RC 接管和取消；
- 对角部、短边入口和退出位置单独拍摄/记录，不能只看最终状态。

**通过条件**：

- 四条边按计划顺序完成；
- 每个转角均在规划安全区域内完成；
- 未发生错误墙切换、越界或旧指令恢复；
- 报告的有效覆盖区间与轨迹/日志一致；
- 角部留白、短边剩余区域和所有未覆盖原因均明确记录。

只有满足这些条件，才能称为“矩形池主要边界区域完成”。

### 阶段 5：凸多边形

**目的**：验证矩形之外的边数、边长和转角变化不会破坏通用逻辑。

**实现内容**：

- 配置支持任意数量的有序顶点；
- 校验顶点无重复、边长超过最小可清洗长度、边界不自交；
- 由顶点生成边段、方向、角度和转移顺序；
- 转角不再假设为 90°，每个转移根据相邻边夹角单独规划；
- 仍复用同一个直边控制器和同一个覆盖率模型。

**验收方法**：

- 先用三角形、梯形和不规则凸五边形进行离线几何测试；
- 再在仿真/回放中验证所有边顺序、端点和扫掠包络；
- 实船先验证一条边到一条边，再验证完整闭环；
- 对锐角、钝角和很短边分别设置失败用例。

**通过条件**：更换边界顶点配置即可执行任务，不需要复制一套矩形控制器；每条边和每个转移均能给出覆盖和失败原因。

### 阶段 6：凹多边形与复杂障碍

**目的**：处理边界有凹角、转移路径可能被池壁或障碍阻挡的区域。

凹多边形不能只把凸多边形流程直接套用。必须增加：

- 船体和刷头的配置空间膨胀；
- 转移路径与边界的碰撞检查；
- 必要时的可见性图或栅格路径搜索；
- 不可达边、不可达转角和跳过边报告；
- 重新规划后的覆盖率统计。

凹多边形通过前，禁止用“沿边走一圈”声明全池完成。若某一边不可达，任务应安全结束并准确报告未完成边。

## 5. 定位验收标准

定位状态至少应包含：

- `map → base_link` 位姿及时间戳；
- 位姿新鲜度和轨迹状态；
- 初始位姿来源（RViz、服务或自动重定位）；
- 扫描与地图匹配/一致性诊断；
- 最近一次跳变、重定位和拒绝原因；
- `LOCALIZATION_READY` 门控结果。

当前 TF 没有可靠协方差时，不能把协方差缺失解释成零误差。第一版可使用地图边界、墙距、墙方向、扫描重合和连续性作为门控；后续再补充定位质量指标。

定位失败或质量下降时的行为固定为：

```text
运动输出关闭 → 保留诊断 → 任务 PAUSED → 不自动恢复
```

## 6. 直边和转移的安全门控

以下条件是运动输出的共同前置条件：

- 使用系统时间，禁止实机输出使用仿真时间；
- bridge 为 READY，租约属于当前任务，connection/epoch 未变化；
- 墙线、位姿和命令均未过期；
- 当前边身份明确，不能处于未确认的墙线关联状态；
- 船体刚性包络和刷头包络通过当前动作检查；
- 扫掠区域没有未知盲区被误当自由空间；
- 动作未超过实测位移、转角、余转和停止时间上限；
- 取消、暂停、RC、断流、时钟故障和超时都能关闭全部辅助输出。

清洗阶段可以在短暂丢墙时进入 `WAIT_WALL`，但转移阶段不能依靠陈旧墙角或旧墙距继续动作。清洗沿边过程不以固定运行时长或预设速度判断完成；仅对数据新鲜度、租约、命令期限和转移动作保留必要的安全超时。

## 8. 当前阻塞项与决策点
