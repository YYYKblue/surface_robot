## 1. 目标与当前边界

目标是让船在预先建立的池体地图中完成以下任务：

1. 通过 Qt App 或 RViz2 标定初始位置和船头方向，完成固定地图定位。
2. 将池边拆成多个长直边，复用同一套沿边控制清洗。
3. 矩形池自动清洗四条边的主要区域，角部保留明确的安全留白。
4. 将同一任务模型扩展到凸多边形，再处理有凹角的多边形。

当前 `f1_pool_cleaning` 已完成两个旧清洗包的合并，并保留：

- 左墙线提取、墙线关联、短暂丢墙恢复和墙线可视化；
- 墙距 32–36 cm 的第五路侧推控制，名义目标 33 cm，默认侧推幅度 50%；
- 沿墙默认以 50% 滚刷推进；启动前可启用四主电机最低档辅助，距墙端/补洗结束位置 >80 cm 且稳定沿墙时生效，进入近端后本墙段锁定关闭，纠偏优先；初始接近和换边仍可使用主电机平移；
- 墙角 ±10° 刷盘门控和 ±3° 连续主电机纠偏；
- 固定地图 `map → base_link` 位姿输入及前墙停车判断；
- 任务租约、遥控接管、数据过期停机和显式 start/cancel 流程。

阶段 2 已加入矩形边界、目标墙关联、靠墙/入口调整、端点停车和左刷接触区间记录；阶段 3 提供相邻边换边状态机。当前阶段 4 由 `AutonomousMission` 编排四条边及必要的起始边前段补齐，默认沿启动时船体 +y 射线选择第一面有限墙段，不固定从 `edge_0` 开始或在 `edge_3` 结束。路线执行结束进入 `COMPLETE`，要求区间是否满足覆盖容差另由 `coverage_complete` 报告，不再搜索其他缺口进行补洗。

阶段 1 正常流程验证通过：新增 `pool_localization_manager`，通过 `/initialpose` 或 `/pool_cleaning/set_initial_pose` 管理 Cartographer 纯定位轨迹；新增 `LOCALIZATION_CHECK`、`LOCALIZATION_READY` 和锁存的 `PAUSED` 门控；控制器在定位未就绪、定位状态过期或定位退化时拒绝启动并关闭输出。阶段 2–4 的软件流程现已接通并覆盖矩形一周任务；异常场景、实船清洁效果和规定次数的重复验收证据仍需补齐，不能仅凭进入 `COMPLETE` 推断池底面积全部覆盖。

定位实现现位于独立的 `f1_localization`。网关组合/受管入口共享 `/f1_localization/*` 定位接口；两个任务分别使用 `/pool_cleaning/*`、`/l_cleaning/*`。App 已支持建图、保存、选图、初始位姿、任务停止与轨迹显示；这些界面能力不替代现场验收。

## 2. 总体架构

```text
冻结地图 pbstream / 栅格地图
             │
             ▼
       定位管理节点
 RViz2 初始位姿 → Cartographer → map → base_link
             │
             ├──────────────┐
             ▼              ▼
      边任务管理器       墙线感知
  当前边/进度/转移阶段   实时墙距/墙角/障碍
             │              │
             └──────┬───────┘
                    ▼
             直边控制器
                    │
                    ▼
              f1_nano_bridge
                    │
                    ▼
                 F103/Nano
```

模块职责必须保持清晰：

| 模块 | 职责 |
|---|---|
| 地图与定位 | 提供稳定、带时间戳的 `map → base_link` 位姿；不直接发执行器指令 |
| 墙线感知 | 从雷达提取当前目标墙，输出墙距、切线角、墙段支持长度和障碍证据 |
| 边任务管理器 | 选择边、判断沿边进度、安排转移和下一条边，不实现电机混控 |
| 直边控制器 | 根据实时墙线维持墙距、航向和刷盘输出 |
| 转移控制器 | 离墙、转向、靠近下一边；使用反馈判断完成 |
| 硬件桥 | 租约、命令期限、方向编码、串口和硬件停止屏障 |

地图位姿负责全局位置和边进度，墙线负责近墙控制。二者的时间戳、坐标系和新鲜度必须分别检查，不能把任一反馈的缺失当作另一反馈有效。

## 3. 任务和数据模型

### 3.1 池边模型

内部模型统一使用有序边段。下面是模型示意，不是可直接传给 ROS 节点的参数 YAML；当前默认从 `map:=` 推导几何，实际参数名和覆盖顺序见[架构导读](../ARCHITECTURE.md#4-地图和参数如何进入控制器)。

```yaml
pool:
  frame: map
  boundary:
    - [x0, y0]
    - [x1, y1]
    - [x2, y2]
    - [x3, y3]
  boundary_order: clockwise
  corner_exclusion_m: 0.30
  wall_target_m: 0.33
  # Boat-centre distance to the front wall at which this edge stops.
  endpoint_margin_m: 0.30
```

实现时每条边应展开为内部结构 `EdgeSegment`，至少包含：

- `id`、起点、终点和单位切向量；
- 墙法向和船应行驶的方向；
- 清洗有效区间、入口和退出位置；
- 目标墙距、终点净空和允许误差；
- 下一条边及其转移方案；
- 计划长度、已清洗区间和未覆盖区间。

阶段 2 只允许配置的池坐标 `+y` 左侧边作为可执行边，使墙始终位于船体左侧，继续复用当前左墙控制。若请求其他边或方向会让墙位于右侧，必须拒绝启动；不能通过符号反转或改写边身份模拟右侧刷墙。其他边应作为后续转移能力实现。

这条限制只描述阶段 2 的单边能力。阶段 3–4 使用顺时针 `EdgeSegment` 路线，在每次换边后重新建立左墙目标，因此当前矩形一周任务可以依次执行四条边；仍不支持用右侧墙线或符号反转绕过左刷模型。

### 3.2 任务状态

带地图的自动任务使用以下阶段。`LOCALIZATION_CHECK/LOCALIZATION_READY` 属于定位管理器，不是清洗运动阶段；选边在 start 请求内同步完成并锁定；没有后台规划线程或独立的 `EDGE_SELECT` 运动状态。

```text
IDLE
  → APPROACH_START
  → 按需 ALIGN_START / MOVE_START_ALONG / MOVE_START_SIDE
  → ACQUIRE_WALL → APPROACH_WALL → APPROACH_EDGE
  → FOLLOW / CORRECT_HEADING / WAIT_WALL
  → 右转换边：EDGE_STOP → MOVE_INWARD → TURN_TO_NEXT_EDGE → APPROACH_NEXT_EDGE
  → 左转换边：EDGE_STOP → LEFT_EXIT_WALL → LEFT_SHIFT_TO_ENTRY
               → TURN_LEFT_TO_NEXT_EDGE → APPROACH_NEXT_EDGE
  → 矩形：其余三边，必要时经相邻转弯补齐起始边前段
  → 开放墙链：当前段及后续段，到链尾前停车，不闭合首尾
  → 本次路线执行结束：COMPLETE（覆盖缺口单独报告）
```

硬件模式在开始靠近前还包含租约获取阶段 `ACQUIRING`，取得租约后保持已锁定的墙和参考点。异常进入 `PAUSED`，用户停止/取消分别为 `STOPPED/CANCELLED`；当前没有 `ABORTED` 或 `FOLLOW_EDGE` 状态。

定位过期/跳变、所需反馈过期、租约失效、RC 接管和时钟故障会关闭输出；转移超时仅在配置启用时适用。靠近阶段只用位姿反馈执行旋转、前后移动和侧移，不做路径搜索、地图足迹或雷达环境碰撞检查。启动前不要求贴墙，进入起始范围后才重新获取有效目标墙；定位管理器的扫描就绪门控仍保留。

`PAUSED` 不因数据恢复自动继续，需检查原因、cancel 后再 start。`STOPPED/CANCELLED/COMPLETE` 可直接开始新的自动任务，重置进度和 `run_id`；不支持断点续跑。

### 阶段 1：定位与 RViz2 初始位姿

**目的**：船下水后位于大致区域，由操作者在 RViz2 标定精确初始位姿，定位节点再输出可靠的 `map → base_link`。

**实现内容**：

1. 启动冻结地图、雷达静态 TF 和定位节点，但不启动运动任务。
2. RViz2 Fixed Frame 设置为 `map`，显示地图、LaserScan、TF 和船体位姿。
3. `2D Pose Estimate` 发布初始位置和朝向；定位管理节点接收并转换为 Cartographer `start_trajectory` 的初始位姿。
4. 初始位姿提交期间保持任务 `IDLE`，禁止申请运动租约。
5. 定位管理节点检查轨迹状态、位姿新鲜度、扫描与地图的重合程度和跳变。
6. 达到稳定条件后发布 `LOCALIZATION_READY`，否则保持 `LOCALIZATION_CHECK`。

当前 `pool_localization.launch.py` 会加载冻结 pbstream、发布雷达静态 TF、启动栅格地图节点发布 `/map`，并启动定位管理器；管理器把 RViz 初始位姿转换为 `StartTrajectory` 请求，查询轨迹状态，并在位姿、扫描、地图边界和扫描端点与 `/map` 占用栅格的重合连续稳定后发布 `LOCALIZATION_READY`。不能把“轨迹创建成功”当成定位正确。

**建议接口**：

- 输入：`/initialpose`，`geometry_msgs/PoseWithCovarianceStamped`；
- 输出：`map → base_link` TF、定位状态和诊断；
- 服务：`/pool_cleaning/set_initial_pose`（`f1_interfaces/SetInitialPose`）、`/pool_cleaning/relocalize`（`std_srvs/Trigger`）；
- 任务门控：没有 `LOCALIZATION_READY` 时 `/pool_cleaning/start` 必须拒绝。

**验收方法**：

- 在地图中至少选择左上、右上、左下、右下四个不同初始区域，各重复 3 次；
- RViz2 标定方向后，TF 的位置和朝向稳定更新；
- 人为给出错误朝向或地图外位置时，任务保持 IDLE 并报告原因；
- 重新定位时不会保留旧任务租约或旧墙线关联；
- 定位节点重启、雷达断流、TF 过期、位姿跳变都不会产生运动输出；
- 保存 RViz 配置、初始位姿、定位状态日志和对应 rosbag。

**软件通过条件**：连续测试覆盖初始位姿校验、轨迹生命周期、TF/扫描过期、地图外位姿、扫描重合不足、位姿跳变和控制器启动门控，默认 `output_enabled=false`。**现场通过条件**仍为四个区域各 3 次完整操作，且保存 RViz 配置、初始位姿、定位状态日志和对应 rosbag；“现场通过前不得进入实船自动换边”是阶段 1 的历史门槛，当前阶段 4 的实船试验仍必须补齐这些定位证据。

**当前记录**：阶段 1 正常流程验证通过；异常场景和重复验收证据待补齐。

### 阶段 2：通用直边控制

**目的**：把当前“左墙单边控制”改造成使用统一 `EdgeSegment` 数据的直边任务，控制算法只保留一份。阶段 2 使用配置的目标边（当前默认 `edge_0`），要求墙位于 `base_link +y`，让单个左侧滚刷稳定刷墙，不包含自动换边。

**实现内容**：

- 用地图位姿将船投影到当前边的切向和法向坐标；
- 根据边方向判断沿程进度、入口和出口；
- 将目标边身份传给墙线感知，防止丢墙后误认相邻墙；
- 继续使用墙线实时控制墙距和夹角；
- 船体按长 0.50 m、宽 0.45 m 的矩形包络建模；左侧唯一滚刷的当前名义中心墙距为 0.33 m，控制区间为 0.32–0.36 m；
- 初始只需在默认目标边附近粗略放置，Cartographer 稳定后将该地图边转换到机器人坐标，先关闭滚刷靠墙并纠正航向，再沿边调整到入口；
- 将终点判断改为当前边终点与船中心的沿程距离，船中心距前方墙约 0.30 m 时停止；
- 当前边进入 `EDGE_STOP` 后关闭刷盘、主电机和第五路输出；
- 记录左侧滚刷接触中心线的有效清洗区间，不把停车、丢墙、暂停或转移区间计入覆盖。

阶段 2 只允许墙位于机器人 `base_link +y` 的 canonical 边作为可执行边，使墙始终位于船体左侧，继续复用当前左墙控制。若请求的边或方向会让墙位于右侧，必须拒绝启动；不能通过符号反转或改写边身份模拟右侧刷墙。

**验收方法**：

- 用同一控制器分别执行矩形四条边，人工只将船粗略放在对应边附近并调整船头方向，使墙位于机器人左侧；
- 每条边的反向请求必须拒绝，不能通过符号反转模拟右侧刷墙；
- 每条边至少执行 3 次粗放置—定位—靠墙—入口调整—直边跟踪流程；
- 检查墙距、墙角符号、边进度和端点停车；
- 端点前后故意加入定位和墙线扰动，确认不会越过安全净空；
- 检查墙线丢失后不会自动切换到相邻墙；
- 用合成反馈、rosbag 回放和 ROS 联调三层测试覆盖相同状态。

**通过条件**：矩形四条边都能使用同一套控制器完成“地图定位—左侧边确认—靠墙调整—入口对齐—直边跟踪—安全停车”；右侧墙线、反向刷墙和自动换边不属于本阶段能力。

### 阶段 3：矩形自动换边

**目的**：完成矩形四条边的通用自动转移；验收仍先以一条边到相邻边的闭环作为最小安全单元。

**当前状态**：已实现。`f1_pool_cleaning` 在每条边端点关闭刷盘和推进，执行停止指令、0.5 s 后退右推和基于地图航向反馈的右转，再进入下一边的目标墙重关联。转移过程中要求地图位姿新鲜；默认不使用固定时间代替转角反馈，暂停后不自动恢复。

**标准流程**：

1. 沿墙阶段到达出口区（船中心距前方墙 0.30 m），进入 `EDGE_STOP`，关刷并停止推进。
2. `MOVE_INWARD` 在一个停止指令周期后，同时发出 `REVERSE` 和向右侧推，默认持续 0.5 s，使船离开当前角部。
3. 后退右推结束后发送一个停止指令周期，并确认地图位姿仍然新鲜。
4. `TURN_TO_NEXT_EDGE` 按目标边方向转动；目标航向进入 ±20° 即视为粗略转向完成，随后由 `APPROACH_NEXT_EDGE` 继续找墙和纠正航向。转向和整段换边的时间超时默认关闭；不能用固定秒数代替角度反馈。
5. `APPROACH_NEXT_EDGE` 接近下一边，重新建立目标墙关联。
6. 目标墙距、墙角和位置稳定后进入下一边的 `FOLLOW/CORRECT_HEADING`。

现场转移验收需要考虑完整船体、刷座和刷头的扫掠范围；当前实现本身只依赖新鲜地图位姿和目标航向反馈，不把静态扫掠检查当成已完成的动态避障。盲区、未知回波或定位退化不能当成自由空间。当前单边控制最多涉及小角度诊断，不能把单边纠偏直接复用于 90° 或 180° 转向。

**验收方法**：

- 先关闭刷盘，在开阔水域做离墙、停止、转向和靠墙的单动作标定；
- 测量每个动作的位移、角度、余转、停止时间和漂移，更新配置；
- 在仿真/回放中验证启用的超时、取消和丢定位分支；当前没有自动障碍避让分支；
- 无障碍条件下完成一次长边到相邻短边的转移；
- 在转移中遮挡雷达或中断定位，确认立即停车且不自动恢复；
- 保留起点、转移轨迹、终点和停止原因。

**软件通过条件**：单条转移状态覆盖停止、后退右推、右转、目标边重关联、反馈过期和取消分支；当前本地任务测试已覆盖这些状态。**现场通过条件**：单条转移路线连续 5 次完成，未碰撞、未越界、未误认墙，转移时间和漂移均处于实测上限内；现场证据仍待归档。

### 阶段 4：矩形四边与覆盖率

**目的**：将简单靠近、四条边、相邻换边和必要的起始边前段补齐串成矩形任务，并独立报告接触区间覆盖。

**当前状态**：默认 `left_ray` 选第一面命中的有限墙段；距公共端点 1 cm 内按有向清洗切线与船头 +x 的夹角选择，相同则按边 ID 排序。无交点拒绝启动，不延长墙段、不回退最近墙。`specified/default_edge_id` 或 `set_edge` 可显式指定起始边，仍采用同一简单靠近流程。起点参考来自船中心的最近投影并按入口/末端余量修正，具体范围见[流程与参数](WALL_CLEANING_FLOW.md)。

首次有效开刷时记录刷头接触位置；其前段超过默认 5 cm 容差时，在其余三边之后通过相邻转弯补齐前段，目标重叠默认 10 cm，并限制在有效清洗区间内。路线结束即 `COMPLETE`；缺口仍保留在 `remaining_contact_intervals`，不触发额外补洗或仅因缺口转入 `PAUSED`。

**实现内容**：

- 从地图推导的矩形边界生成 4 个 `EdgeSegment`；
- 为每条边单独计算入口、出口、端部留白和允许清洗区间；
- 按配置的端部留白、停止距离和换边参数执行转移；船体扫掠、刷头覆盖和停止漂移作为现场验收数据记录，当前代码不自动生成动态障碍安全区域；
- 维护 `current_edge_id`、`completed_edges`、`cleaned_intervals` 和 `uncovered_intervals`；
- `executed_edge_ids` 记录已经执行结束的边，`completed_edges` 记录已满足覆盖容差的边，二者可能不同；`cleaned_intervals_by_edge` 保存累计覆盖，最终结合要求区间与剩余缺口归档报告；
- 自动任务另提供 `required_contact_intervals`、`remaining_contact_intervals`、`first_brush_contact`、`returning_to_start`、`executed_edge_ids`、`coverage_complete` 和 `expected_track`；App 的实际 TF 轨迹由网关采样，不替代控制器覆盖判据；
- 角部不要求刷到，但角部留白必须可配置、可显示、可审计。

示例地图 `lidar_20261021_145054` 的墙带估计约为 2.883 m × 1.520 m，当前配置不固定这些数值。要求接触区间由端部边距、刷盘纵向偏移和前墙停车阈值确定；相邻换边仍使用船中心到前墙约 30 cm 的停止条件。`expected_track` 是各边的清洗目标段和起始范围，不是可达路径；`navigation_path` 保留为空列表。启动不检查路径可达性，不能由启动成功推断所有短边都可清洗。

**验收方法**：

- 先使用 `output_enabled=false` 完成全流程回放和预览；
- 将单动作标定与完整任务验收分开：当前直边推进依赖滚刷，`brush_percent=0` 不受配置支持，不能据此运行“无刷完整四边”；
- 在已核对方向、停车和转移动作后，按当前开刷控制逻辑验证完整任务；
- 四边各至少重复 3 次，记录每条边起止点和未覆盖区间；
- 对矩形整体执行一次完整任务，验证中途暂停、重新定位、RC 接管和取消；
- 对角部、短边入口和退出位置单独拍摄/记录，不能只看最终状态。

**通过条件**：

- 四条边按计划顺序完成；
- 每个转角的实际轨迹、余转和漂移符合现场确认的空间范围；
- 未发生错误墙切换、越界或旧指令恢复；
- 报告的有效覆盖区间与轨迹/日志一致；
- 角部留白、短边剩余区域和所有未覆盖原因均明确记录。

只有满足这些条件，才能称为“矩形池主要边界区域完成”。

**当前判定**：软件流程已满足四边编排、自动换边、完成状态和按边区间记录；上述现场条件仍需通过单动作标定、开刷任务和规定次数的实船重复试验后，才能将某次运行记为“矩形池主要边界区域完成”。

### 阶段 5：凸多边形

**目的**：验证矩形之外的边数、边长和转角变化不会破坏通用逻辑。

**实现内容**：

- 配置支持任意数量的有序顶点；
- 校验顶点无重复、边长超过最小可清洗长度、边界不自交；
- 由顶点生成边段、方向、角度和转移顺序；
- 转角不再假设为 90°，每个转移根据相邻边夹角单独规划；
- 仍复用同一个直边控制器和同一个覆盖率模型。

**验收方法**：

- 先用三角形、梯形和不规则凸五边形进行离线几何测试；
- 再在仿真/回放中验证所有边顺序、端点和扫掠包络；
- 实船先验证一条边到一条边，再验证完整闭环；
- 对锐角、钝角和很短边分别设置失败用例。

**通过条件**：更换边界顶点配置即可执行任务，不需要复制一套矩形控制器；每条边和每个转移均能给出覆盖和失败原因。

### 阶段 6：凹多边形与复杂障碍

**目的**：处理边界有凹角、转移路径可能被池壁或障碍阻挡的区域。

凹多边形不能只把凸多边形流程直接套用。必须增加：

- 船体和刷头的配置空间膨胀；
- 转移路径与边界的碰撞检查；
- 必要时的可见性图或栅格路径搜索；
- 不可达边、不可达转角和跳过边报告；
- 重新规划后的覆盖率统计。

凹多边形通过前，禁止用“沿边走一圈”声明全池完成。若某一边不可达，任务应安全结束并准确报告未完成边。

## 5. 定位验收标准

定位状态至少应包含：

- `map → base_link` 位姿及时间戳；
- 位姿新鲜度和轨迹状态；
- 初始位姿来源（RViz、服务或自动重定位）；
- 扫描与地图匹配/一致性诊断；
- 最近一次跳变、重定位和拒绝原因；
- `LOCALIZATION_READY` 门控结果。

当前 TF 没有可靠协方差时，不能把协方差缺失解释成零误差。第一版可使用地图边界、墙距、墙方向、扫描重合和连续性作为门控；后续再补充定位质量指标。

定位失败或质量下降时的行为固定为：

```text
运动输出关闭 → 保留诊断 → 任务 PAUSED → 不自动恢复
```

## 6. 直边和转移的安全门控

以下按阶段说明当前门控；现场测量要求不代表代码具备自动环境碰撞检查：

- 使用系统时间，禁止实机输出使用仿真时间；
- 实机申请租约前 bridge 为 READY，运动时租约属于当前任务，connection/epoch 未变化；
- 靠近阶段要求位姿和命令未过期；`ACQUIRE_WALL` 停止输出并等待进入范围后的新墙观测，默认 1.5 s 超时暂停；沿墙阶段另要求墙观测新鲜；
- 起始边在 start 时锁定，靠近期间不要求已关联墙线；确认墙面后和相邻换边后均使用对应目标墙身份；
- 转移动作使用新鲜地图位姿和目标航向反馈；当前实现不以静态船体/刷头扫掠检查代替现场观察；
- 现场操作不得把雷达未知盲区当成自由空间；软件当前不能发现盲区中的新增障碍；
- 默认 `run_timeout_sec`、`transfer_timeout_sec` 和 `transfer_turn_timeout_sec` 均为 0（关闭）；实测位移、余转和停止时间用于现场验收，代码不自动以这些实测上限进行门控；
- 取消、暂停、RC、断流、时钟故障和超时都能关闭全部辅助输出。

清洗阶段可以在短暂丢墙时进入 `WAIT_WALL`，但转移阶段不能依靠陈旧墙角或旧墙距继续动作。清洗沿边过程不以固定运行时长或预设速度判断完成；数据新鲜度、租约和命令期限检查持续生效，转移时间超时仅在配置启用时生效。

## 8. 当前阻塞项与决策点

矩形自动清洁一周的软件流程不再被接口、状态机或四边编排阻塞。当前仍需形成实测或配置结论的项目是：

1. 冻结地图定位的现场稳定性、地图尺度和地图边界误差；软件已具备 RViz 初始位姿到 Cartographer 纯定位轨迹的转换和就绪门控。
2. 第五路正负方向、主电机 LEFT/RIGHT 与实船动作的对应关系，以及离墙、停止、转角和靠近动作的位移、余转和漂移上限。
3. 雷达盲区、船体转动和刷头扫掠过程中的可见性。当前换边依赖新鲜地图位姿和连续航向反馈，不能把未知盲区当成自由空间。
4. 刷头实际接触位置、有效覆盖宽度、角部留白和短边有效清洗长度；这些数据决定覆盖报告如何解释。
5. 基本测试的详细场景、单动作与开刷任务的重复运行记录，包括暂停、取消、遥控接管和异常停机。
6. 凸多边形和凹多边形的转移规划；它们不是当前矩形一周能力的一部分。

这些现场记录项不都是自动 `PAUSED` 条件；代码按定位、反馈、租约及状态机规则决定暂停。后退右推仍使用配置的 0.5 s，转角与靠近完成仍由位姿反馈决定。

## 10. 开放多段直墙专项：`f1_l_cleaning`

当前包复用共享墙感知、直边控制、租约和硬件桥，执行有方向的开放墙链。地图提取按最大空闲连通域外轮廓分段拟合，保留有左墙、右侧水域支持的直墙；持续缺墙、未知边界和曲线会断开或被拒绝。候选链按长度降序排列，默认 `route_chain_index=0`；不同链不拼接、不自动转场，首尾不闭合。完整闭合矩形使用矩形任务。

默认示例地图 `lidar_20261026_170703` 包含五段：阶梯三条短墙接原大 L 下边和左边，约 1.00 / 2.07 / 1.26 / 8.91 / 11.84 m，转向依次为右、右、左、右。原大 L 两条边现为 `edge_3/edge_4`；这些是地图拟合结果，不是实测验收点。2026-10-27 的两段 `A → B → C` 及 `edge_0/edge_1` 编号只适用于旧路线，现场指定起始边前应运行 `map_profile <地图> --json` 重新核对。

启动入口为 `f1_l_cleaning/l_bringup.launch.py`，必须传 `map:=`，默认预览且不自动 start。独立入口使用 `/l_cleaning/*` 定位与任务接口；网关组合/受管入口共享 `/f1_localization/*` 定位，任务仍为 `/l_cleaning/*`，协议类型仍为 `l`。参数和操作见[开放任务说明](../../src/f1_l_cleaning/README.md)。

右转换边沿用“关刷停止周期 → 后退与右推 0.50 s → 停止 → 地图航向右转 → 新墙关联”。左转换边为“关刷前行出墙端 → 保持旧航向左移至新墙入口沿程位置 → 左转 → 新墙关联”；前行目标至少超过旧墙端 `left_exit_forward_m=0.35 m`，并考虑下一入口投影，位置容差 `left_transfer_position_tolerance_m=0.05 m`。转向容差默认 ±20°，转移/转向超时默认关闭；这些值不构成船体净空保证。

自动任务从选中墙的当前位置开始，只执行后续墙段，到链尾前约 30 cm 停止。初始参考点取船中心最近投影；指定 `edge_0` 不会自动回到整条链起点。要清洗全链，应从首边入口附近开始。`completion_scope=remaining_open_route`；起始边首次有效开刷位置之前的部分不属于本次要求区间，路线完成与覆盖缺口独立报告。

专项验收包括：

- 地图提取：单墙、多段混合转向、旋转/不同分辨率、短墙、缺墙断开、独立链选择、拒绝闭合或无效路线。
- 动作：原右转回归、45°/90°/135°左转、前行/侧移到位、航向纠偏及动作切换停止周期，换边期间关刷并禁用旧墙目标。
- 接口：转后目标代次递增、旧墙观测拒绝、命名空间隔离、定位范围加载和默认无硬件输出。
