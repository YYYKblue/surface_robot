# F1 Windows 操作员 Qt App

更新：2026-11-09。App 通过 WebSocket 连接 Nano 网关，不需要安装 ROS，不管理控制 token。

当前功能包括建图、地图命名保存、地图列表/预览/加载、手动控制、底图与实时船体位姿、开放多边／矩形任务选择、地图初始位姿发布、启动条件显示、任务完成结果、实际轨迹、任务停止/取消、船体中心距左墙显示及诊断日志导出。App 不再显示雷达点、预期轨迹、起始范围框或停车点；ROS 雷达和任务控制算法继续正常运行。

2026-11-09 的显示链路更新必须同时升级 Nano 网关与整个 Windows App，exe 需要重新打包。新版地图采用压缩编码，轨迹和诊断采用独立消息，旧 App 无法完整显示新版网关数据。

## 启动与打包

Nano 启动方式见[网关说明](../src/f1_operator_gateway/README.md)。在 Windows 执行：

```powershell
cd operator_app
python -m pip install -r requirements.txt
python main.py --url ws://192.168.1.188:8765
```

使用 PySide6，也兼容开发环境中的 PyQt5。打包必须在 Windows 上执行：

```powershell
python -m pip install pyinstaller
pyinstaller --noconsole --name F1Operator main.py
```

分发整个 `dist/F1Operator/` 目录。`--onefile` 可生成单文件版本。

## 建图与选图

Nano 使用新入口（无需已有地图；雷达沿用现有常驻驱动）：

```bash
ros2 launch f1_operator_gateway operator_system.launch.py \
  workspace_root:=/home/nvidia/surface_ws bind_address:=0.0.0.0
```

默认关闭硬件输出；实机核对桥配置后显式设置 `output_enabled:=true`。部署开机服务见 [Nano 部署指南](../DEPLOY_NANO.md#app-建图选图与开机服务)。旧的单独网关/组合入口仍保留，但不提供 App 建图和选图能力。

1. 在“建图与选图”页点击“开始建图”；需要新鲜有效的 `/pavo2_scan`，不能有清洗任务或未确认的任务操作。
2. 切到“手动控制”，缓慢操船探索，查看低频更新的地图与实时船头。建图地图默认最多每 2 秒更新一次，位姿独立按核心遥测更新；建图不需要固定地图初始位姿，不包含自主探索。
3. 地图名称可留空，Nano 按配置时区生成 `YYYYMMDD_HHMMSS`；自拟名称支持中文、字母、数字、下划线、短横线，最多 80 字符。重名自动追加序号，不覆盖旧地图。
4. “保存快照”生成同名 `.pbstream/.pgm/.yaml` 并继续建图；“保存并结束”在三份文件保存成功后退出。保存时暂停手动输出，完成后需重新操作才运动。
5. 保存失败不会自动结束建图。若 pbstream 已成功写出，刷新列表后可选择“待导出”条目，点击“重试所选快照导出”；重试仅补全原快照，不代表保存了之后探索的区域。
6. 保存完成后列表自动刷新并选中新地图。点击“使用此地图”启动固定地图定位及该地图支持的清洗控制器，然后在“清洗任务”中设置初始位姿。

地图保存到 **Nano 的 `workspace_root/maps/`**，不保存到 Windows，也不自动同步到开发电脑。界面显示最终名称和绝对路径。列表显示文件完整性、修改时间和失败原因；损坏/缺失的地图不能加载。“预览所选地图”打开独立窗口，不叠加当前位姿、雷达或清洗轨迹，也不改变当前使用地图。

建图与固定地图定位互斥。选图前先保存并结束或明确放弃当前建图；清洗期间先停止任务并等待确认。地图加载后必须重新设置初始位姿，不自动开始清洗。未能推导矩形/开放墙链路线的类型保持不可用，地图保存成功不等于适合自动清洗。

名称输入框和数值输入框获得焦点时停止手动输出，W/A/S/D 与空格只用于文字输入；返回驾驶控件后再操船。窗口失去焦点也停止手动输出。

App 断线后自动重连，不重放旧运动或离散命令。断线会停止手动输出，但已启动的建图和已接受的保存继续在 Nano 运行；重连读取实际会话和最近保存结果。退出 App 不自动结束建图。Nano 进程重启/掉电不能恢复未保存 SLAM，会保留已写出的文件及可重试快照。

## 清洗操作

“主电机提速”按钮默认关闭，在任务开始前按当前任务类型设置；运行中、获取控制权和暂停时锁定，暂停后需先取消。停止/完成后可为下一次任务修改。开启后，正常沿墙且船中心沿当前墙方向距墙端大于 80 cm 时，四电推以新标度 25% 前进辅助；80 cm 内（含边界）撤销辅助，本墙段不再恢复，仍允许航向纠偏。矩形补洗还会在实际任务结束位置前 80 cm 撤销辅助。

按钮显示 Nano 已确认的开关，旁边区分正在提速、纠偏、近端区和等待沿墙等状态。请求期间禁用重复设置和开始任务；失败或超时不显示为已成功开启。断线重连读取实际设置，不重放旧操作。开关在当前控制器会话内保留，重新加载地图或控制器重启后默认关闭。旧网关/控制器不支持时按钮禁用；需要同步更新 Nano 和 Windows App，使用 exe 时重新打包。

1. 在“清洗任务”中选择“开放多边清洗”或“矩形清洗”。当前地图无法推导路线、节点未运行或状态过期时，对应选项不可用；悬停可查看原因。
2. 点击“设置初始位置和船头方向”，在地图上按住鼠标并拖动。紫色箭头表示待发布位置及船头方向；拖动至少 8 像素以确定方向。
3. 检查预览，点击“发布初始位姿”。这与 RViz 的 `2D Pose Estimate` 使用同一定位管理器。
4. 等待定位稳定、雷达和位姿反馈正常，以及控制器启动检查通过。“开始清洗”此前保持禁用。
5. 开始后显示锁定的起始墙，以及获取控制权、调整船头、前后调整、侧移靠近、确认墙面、清洗、换边等阶段。默认从船中心沿船体左侧（+y）射线选墙，角点按清洗方向与船头（+x）的夹角选墙；墙上参考点来自中心最近投影。左侧射线未命中任务墙时启动被拒绝，需调整朝向。靠近不做路径搜索或环境碰撞检查。
6. `COMPLETE` 显示本次路线执行完成与时间，并单独显示覆盖记录是否有缺口。矩形仅绕行补齐起始边前段；开放墙链只执行起始位置之后到链尾的路线，不返回、不补洗。预览模式标注“不驱动硬件”；结果保留到同类型的新任务开始。

定位界面显示机器人端的稳定窗口，不在 Windows 端自行倒计时放行。定位默认要求连续 1 秒通过轨迹、新鲜度、范围、跳变、雷达和扫描/地图匹配检查；这不等同于船体静止或实测定位精度。任务和定位地图必须一致。

“定位：已稳定”和“雷达／位姿：正常”来自共享定位状态；“开始清洗”还要求当前选中任务的 `can_start=true`，以及遥测新鲜、操作权限和无待确认操作等条件。矩形 `/pool_controller` 与开放多边 `/l_controller` 各自检查反馈，切换下拉框只切换读取的任务状态。两者标准配置均使用 TF 位姿并要求定位就绪，但控制器对位姿源数据年龄、距最近一次接收新位姿的时间均默认要求小于 250 ms；所以定位正常时，两类任务的启动可用状态仍可能不同。

“反馈数据未就绪”“位姿数据未就绪”只是阻断原因的中文分类，不能仅凭这两行判断为上报延迟。悬停启动条件文字可查看原文：`pose receive stream stopped` 表示没有持续收到新位姿；`fresh fixed-map base_link pose required` 表示控制器没有可用位姿；`pose stale or future stamped` 表示已有位姿的时间戳无效、过旧或在未来。结合实际参数与原文排查，见[定位正常但开放任务不能启动](../DEPLOY_NANO.md#定位正常但开放任务不能启动)。

2026-11-09 修复了 Nano 受管启动链中的空配置继承问题：App 加载地图经 `operator_system → runtime → operator_mode → operator_bringup` 启动任务时，空 `rectangle_config` / `l_config` 现明确回退各包默认 YAML；显式指定的路径不存在或是目录则启动报错。该修复确保控制器加载配置，没有改变 App 的启动判定、选墙或运动规则。

“开始清洗”可用表示启动前置门控通过，选墙交点与起始区间仍在实际 start 请求中校验。开放墙链从中途开始只执行选中位置及后续边；若要清洗整条链，应由操作者先移动至首边入口附近。墙链索引由 Nano 的 `l_config` 中 `route_chain_index` 配置，App 不提供切换独立墙链的控件。确认墙面超时会暂停；检查原因、取消后重新开始。

运行或操作处理中不能更换任务类型、重新设置位姿或发送手动运动。暂停不支持断点继续，需取消后重新开始；自动任务完成后可直接开始新任务。任务类型选择不切换定位地图；使用受管入口时到“建图与选图”加载地图并重新定位，旧入口仍需在 Nano 重启对应配置。

## 手动控制与停止

更新后的 F103 协议 v3 支持主驱动整数 `0–100%`。手动页提供滑条、整数输入框及 `25% / 50% / 75%` 快捷按钮，默认 25%。它表示主电机 PWM 输出幅度：100% 对应相对中位最大 ±400 μs；25% 对应 ±100 μs。物理遥控器仍使用原三档，其 25 档为 ±125 μs，因此 App 百分比与遥控器档位不能直接视为同一标度，也不表示实测船速。

滑条和快捷按钮不获取键盘焦点，按住 W/A/S/D 时可调整输出。调到 0 会立即清除主方向与按键保持状态，但保留独立滚刷、第五电推设置；再次调高不会恢复旧运动，需要重新按方向。数值输入框获得焦点时沿用“停止全部手动输出”的规则；输入完成按 Enter 返回驾驶焦点。顶部停止按钮仍会关闭全部手动输出。

连续输出通过 `hello.capabilities` 中的 `continuous_drive_percent_v1` 协商，`hello` 和遥测的 `drive_output` 提供 `min=0/max=100/step=1/firmware_protocol_version=3/available`。新版网关尚未确认兼容固件或报告不可用时，App 禁止手动输出并显示原因；缺失或无效能力数据同样禁止。手动输出还要求 Nano 控制源、READY/ACTIVE 状态、已解锁、结果 OK，以及新鲜 CTRL/ACK。串口连接、控制源或 epoch 改变时发送停止并清除旧按住动作；即使 RC 接管后已回到 READY，也要重新按方向。旧网关未声明该能力时，界面回退到原有 25/50/75 三档。App 请求与 F103 回报的控制源、方向、输出值分别显示，RC 回报明确标为遥控器档位；过期状态不显示为当前回报。

### 诊断日志

右侧新增“诊断日志”页，记录连接/重连、手动按钮禁用原因、窗口失焦、输入框焦点、App 手动意图刷新定时器延迟，以及网关和串口桥的停止原因。手动页也直接显示当前按钮禁用原因。

- 网关 `input_timeout` 带接收输入间隔和超时阈值；桥状态记录 `command deadline expired`、`CTRL timeout`、`ACK progress timeout` 等原始原因及 CTRL/ACK 年龄、指令剩余时间。
- 诊断页显示 F103 协议版本、兼容性、四路目标 PWM（BL/BR/FL/FR）、发送与 ACK 序号；这些是指令目标/接收状态，不是实际电机转速、推力或船速。RC 的有效标记、flags、帧序号、年龄及 CH1–CH14 只用于诊断，App 不能从这些字段控制遥控器。
- ROS 桥持续发遥测不代表串口反馈仍新鲜：F103 方向/输出值和目标 PWM 还需串口连接有效、CTRL 年龄小于 400 ms；RC 原始通道独立要求有效帧且遥测年龄小于 400 ms（接收机本身 100 ms 失联由固件有效标记反映）。显示时计入网关缓存 ControlState 的年龄、App 收包后的等待和网关已知排队时间，过期目标/原始通道隐藏，协议不兼容原因仍可查看。这些仅是显示判定，不修改控制超时。
- App 保留最近 2000 条，支持展开查看、复制、导出带 BOM 的 UTF-8 文本和清空。日志仅在本次 App 运行期间保留，关闭前请导出。
- 更新 Nano 的 `f1_operator_gateway` 后，网关暂存最近 50 条事件，App 重连时补读并去重。网关重启会丢失此前尚未收到的历史；事件超出保留数量时会提示缺失。
- 仅更新 Windows App 也能查看本地事件和收到的桥状态，但旧网关无法补传断线期间的停止原因。Nano 事件时间和 App 本地时间均带时区，跨机器时间可能有偏差，日志按接收顺序显示。
- 界面定时器延迟仅表示 App 调度间隔变大，不能单独证明网络故障；需结合网关 `input_age_ms`、桥的 `last_stop_reason` 判断。
- `gui_input_expired` 表示 GUI 超过 250 ms 没有刷新操作意图，后台主动停止并锁住旧意图；界面恢复后先清除方向、按键、刷子和推力，再允许新操作。导出日志前会主动发送 `diagnostics_export` 停止，避免原生保存对话框阻塞 GUI 时仍保留运动意图。

部署需要同步更新 Windows 的 `operator_app`（使用 exe 时重新打包），并在 Nano 重建、重启网关。本次日志功能没有调整控制超时阈值。

W/A/S/D 和方向按钮按住运行、松开停止主驱动。滚刷与第五电推仍独立控制，范围 `-100%` 至 `100%`。

手动输入由独立发送线程按 50 ms 节拍发送，不等待遥测完整接收或地图解析。GUI 定时器只更新操作意图快照和存活时间；方向按下/松开、辅助执行器变化会立即更新快照。短于 250 ms 的 GUI 刷新间隔抖动不再直接决定网络发送间隔，但后台不会无限重发旧动作。窗口失焦、触摸取消、手动锁定和离散操作都会撤销后台意图；自动重复键盘事件不能复活已经过期的按住动作。每次重连必须重新完成握手，旧连接的动作和未确认操作不会补发。

这项 App 修改保持 WebSocket 协议、网关 250 ms 手动输入看门狗、串口桥 250 ms 指令有效期和 App 800 ms 遥测门控不变。使用 exe 时需在 Windows 重新打包；本地测试通过不代表已验证 Windows 平板、Wi-Fi 或实船。网络本身中断或 GUI 严重停顿时，停止保护仍会生效。

顶部红色按钮已更名为“停止手动输出”；空格键作用相同。它只发送 `manual_stop`，**自动任务使用任务面板中的“停止任务”“取消任务”或“暂停任务”**。App 断线不主动取消自动任务。断线或遥测超过 0.8 秒未更新时，App 清除旧位姿并禁用开始；不重发旧操作。遥测年龄从网络线程实际收包时刻计算，并计入网关已知排队时间；GUI 处理旧包不会将其重新判为新鲜。手动按钮被禁用时先把按钮焦点移到主窗口，避免自动跳入数值输入框；用户主动编辑数值时仍停止手动输出。

网关负责手动租约释放与自动任务启动的交接。离散操作有请求编号和反馈；实时手动输入只保留最新值，不会覆盖初始位姿或任务命令。操作超时表示结果未确认，不能视为已停止或未执行。

任务按钮含义：

| 按钮 | 后端状态与行为 |
|---|---|
| 暂停任务 | `PAUSED`，关闭输出；需取消后重新开始 |
| 停止任务 | `STOPPED`，关闭输出、释放任务租约，保留进度和历史轨迹；再次开始创建新任务 |
| 取消任务 | `CANCELLED`，关闭输出、释放任务租约，并清除当前边关联；历史轨迹仍可查看 |

按钮响应成功表示控制器已处理请求；界面以新的任务状态显示结果，不表示船体因惯性产生的漂移已经停止。启动请求尚未返回时点击停止/取消，网关会按顺序完成停止，防止迟到的启动响应覆盖用户意图。

## 轨迹与墙距

- 绿色实线：本次任务运行期间的 TF `map → base_link` 历史轨迹，与当前绿色船头箭头对应。只在任务/定位状态有效时采样，约不高于 5 Hz、移动至少 3 cm 才追加；定位中断、重新初始化、时间回退、采样间隔超过 0.6 秒或位置跳变超过 0.35 m 时断线，不连接未知运动。
- 每种任务在网关内最多保留最近 2000 点，超限会明确提示。停止、取消、完成后保留；新任务或地图身份变化时重置。App 重新连接同一网关可恢复，网关重启后不恢复，不写入磁盘。网关中途启动只能记录启动后的部分轨迹。
- 地图下方显示船体中心距左墙，单位 m/cm。测量基准为 `base_link` 原点，使用雷达拟合左墙线的垂直距离；不是滚刷间隙，也不是船体到任意最近障碍物的距离。墙观测无效、源时间戳/接收时间过期或遥测过期时显示“无有效观测”，不沿用旧值。

轨迹只显示当前选择任务的实际行驶历史，并校验网关会话、地图、坐标系和 run_id。采样与上报分开：网关最多每 0.5 秒发送一次变化后的实际轨迹，核心状态和船体位姿仍默认 10 Hz。遥测过期后保留历史轨迹并标注过期，隐藏实时船头。手动驾驶或建图期间未运行清洗任务时，不新增任务历史轨迹。`--mock` 使用同样的独立轨迹消息，但仅为 UI 演示。

## 地图与坐标

船头箭头直接使用 TF `map → base_link` 的航向，初始位姿也以 `base_link` 为准。屏幕/地图转换包含分辨率、地图原点旋转、窗口缩放及 Y 轴翻转。

受管固定地图定位模式在本次地图会话首次加载后保持底图静态，重新加载地图时刷新；建图模式默认最多每 2 秒编码一次最新地图。网关后台将显示栅格映射为三色索引并 zlib 压缩，不改变 ROS 原图的分辨率、原点或控制用途。App 在独立后台线程解压、创建 QImage；GUI 缓存缩放底图和实际轨迹坐标，合并重复绘制请求。地图预览仍兼容旧数组格式。

网关和 App 对遥测、地图、轨迹各只保留一份最新待处理数据；操作回复与诊断事件走独立的有界可靠队列。慢链路超过发送期限或可靠队列溢出会明确断开并重连，未确认操作不会自动重发。日志中的 UI 等待时间、网关排队时间和 stream 序号用于区分积压位置；两端系统时钟不用于直接相减计算网络时延。

现场应与 RViz 对照同一点、同一船头方向后验收；软件测试不替代实际安装方向核对。
