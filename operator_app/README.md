# F1 Windows 操作员 Qt App

更新：2026-10-31。App 通过 WebSocket 连接 Nano 网关，不需要安装 ROS，不管理控制 token。

当前功能包括建图、地图命名保存、地图列表/预览/加载、手动控制、地图与雷达显示、L／矩形任务选择、地图初始位姿发布、启动条件显示、任务完成结果、预期与实际轨迹、任务停止/取消以及船体中心距左墙显示。

## 启动与打包

Nano 启动方式见[网关说明](../src/f1_operator_gateway/README.md)。在 Windows 执行：

```powershell
cd operator_app
python -m pip install -r requirements.txt
python main.py --url ws://192.168.1.188:8765
```

使用 PySide6，也兼容开发环境中的 PyQt5。打包必须在 Windows 上执行：

```powershell
python -m pip install pyinstaller
pyinstaller --noconsole --name F1Operator main.py
```

分发整个 `dist/F1Operator/` 目录。`--onefile` 可生成单文件版本。

## 建图与选图

Nano 使用新入口（无需已有地图；雷达沿用现有常驻驱动）：

```bash
ros2 launch f1_operator_gateway operator_system.launch.py \
  workspace_root:=/home/nvidia/surface_ws bind_address:=0.0.0.0
```

默认关闭硬件输出；实机核对桥配置后显式设置 `output_enabled:=true`。部署开机服务见 [Nano 部署指南](../DEPLOY_NANO.md#app-建图选图与开机服务)。旧的单独网关/组合入口仍保留，但不提供 App 建图和选图能力。

1. 在“建图与选图”页点击“开始建图”；需要新鲜有效的 `/pavo2_scan`，不能有清洗任务或未确认的任务操作。
2. 切到“手动控制”，缓慢操船探索，查看实时地图、船头和雷达。建图不需要固定地图初始位姿，不包含自主探索。
3. 地图名称可留空，Nano 按配置时区生成 `YYYYMMDD_HHMMSS`；自拟名称支持中文、字母、数字、下划线、短横线，最多 80 字符。重名自动追加序号，不覆盖旧地图。
4. “保存快照”生成同名 `.pbstream/.pgm/.yaml` 并继续建图；“保存并结束”在三份文件保存成功后退出。保存时暂停手动输出，完成后需重新操作才运动。
5. 保存失败不会自动结束建图。若 pbstream 已成功写出，刷新列表后可选择“待导出”条目，点击“重试所选快照导出”；重试仅补全原快照，不代表保存了之后探索的区域。
6. 保存完成后列表自动刷新并选中新地图。点击“使用此地图”启动固定地图定位及该地图支持的清洗控制器，然后在“清洗任务”中设置初始位姿。

地图保存到 **Nano 的 `workspace_root/maps/`**，不保存到 Windows，也不自动同步到开发电脑。界面显示最终名称和绝对路径。列表显示文件完整性、修改时间和失败原因；损坏/缺失的地图不能加载。“预览所选地图”打开独立窗口，不叠加当前位姿、雷达或清洗轨迹，也不改变当前使用地图。

建图与固定地图定位互斥。选图前先保存并结束或明确放弃当前建图；清洗期间先停止任务并等待确认。地图加载后必须重新设置初始位姿，不自动开始清洗。未能推导矩形/L 路线的类型保持不可用，地图保存成功不等于适合自动清洗。

名称输入框和数值输入框获得焦点时停止手动输出，W/A/S/D 与空格只用于文字输入；返回驾驶控件后再操船。窗口失去焦点也停止手动输出。

App 断线后自动重连，不重放旧运动或离散命令。断线会停止手动输出，但已启动的建图和已接受的保存继续在 Nano 运行；重连读取实际会话和最近保存结果。退出 App 不自动结束建图。Nano 进程重启/掉电不能恢复未保存 SLAM，会保留已写出的文件及可重试快照。

## 清洗操作

1. 在“清洗任务”中选择 L 清洗或矩形清洗。当前地图无法推导路线、节点未运行或状态过期时，对应选项不可用；悬停可查看原因。
2. 点击“设置初始位置和船头方向”，在地图上按住鼠标并拖动。紫色箭头表示待发布位置及船头方向；拖动至少 8 像素以确定方向。
3. 检查预览，点击“发布初始位姿”。这与 RViz 的 `2D Pose Estimate` 使用同一定位管理器。
4. 等待定位稳定、雷达和位姿反馈正常，以及控制器启动检查通过。“开始清洗”此前保持禁用。
5. 开始后显示获取控制权、规划、导航、找墙、清洗、换边等阶段。规划仍可能失败，启动条件通过不等于路线一定可完成。
6. 控制器进入 `COMPLETE` 后显示“任务完成”、完成时间和边数。预览模式明确标注“不驱动硬件”；结果保留到同类型的新任务开始。

定位界面显示机器人端的稳定窗口，不在 Windows 端自行倒计时放行。定位默认要求连续 1 秒通过轨迹、新鲜度、范围、跳变、雷达和扫描/地图匹配检查；这不等同于船体静止或实测定位精度。任务和定位地图必须一致。

运行或操作处理中不能更换任务类型、重新设置位姿或发送手动运动。暂停不支持断点继续，需取消后重新开始；自动任务完成后可直接开始新任务。任务类型选择不切换定位地图；使用受管入口时到“建图与选图”加载地图并重新定位，旧入口仍需在 Nano 重启对应配置。

## 手动控制与停止

W/A/S/D 和方向按钮按住运行、松开停止主驱动。滚刷与第五电推仍独立控制，范围 `-100%` 至 `100%`。

顶部红色按钮已更名为“停止手动输出”；空格键作用相同。它只发送 `manual_stop`，**自动任务使用任务面板中的“停止任务”“取消任务”或“暂停任务”**。App 断线不主动取消自动任务。断线或遥测超过 0.8 秒未更新时，App 清除显示中的旧位姿/雷达并禁用开始；不重发旧操作。

网关负责手动租约释放与自动任务启动的交接。离散操作有请求编号和反馈；实时手动输入只保留最新值，不会覆盖初始位姿或任务命令。操作超时表示结果未确认，不能视为已停止或未执行。

任务按钮含义：

| 按钮 | 后端状态与行为 |
|---|---|
| 暂停任务 | `PAUSED`，关闭输出；需取消后重新开始 |
| 停止任务 | `STOPPED`，关闭输出、释放任务租约，保留进度和历史轨迹；再次开始创建新任务 |
| 取消任务 | `CANCELLED`，关闭输出、释放任务租约，并清除当前边关联；历史轨迹仍可查看 |

按钮响应成功表示控制器已处理请求；界面以新的任务状态显示结果，不表示船体因惯性产生的漂移已经停止。启动请求尚未返回时点击停止/取消，网关会按顺序完成停止，防止迟到的启动响应覆盖用户意图。

## 轨迹与墙距

- 蓝色虚线：按船体中心及目标墙距计算的清洗目标线。规划前显示配置区间，规划后使用可执行的要求区间；各条边独立绘制，L 路线不闭合。这不是提前规划出的整场转弯/避障轨迹。
- 紫色虚线：控制器当前导航到清洗起点的规划路径，仅在导航/调整姿态阶段显示；重规划后更新。
- 绿色实线：本次任务运行期间的 TF `map → base_link` 历史轨迹，与当前绿色船头箭头对应。只在任务/定位状态有效时采样，约不高于 5 Hz、移动至少 3 cm 才追加；定位中断、重新初始化、时间回退、采样间隔超过 0.6 秒或位置跳变超过 0.35 m 时断线，不连接未知运动。
- 每种任务在网关内最多保留最近 2000 点，超限会明确提示。停止、取消、完成后保留；新任务或地图身份变化时重置。App 重新连接同一网关可恢复，网关重启后不恢复，不写入磁盘。网关中途启动只能记录启动后的部分轨迹。
- 地图下方显示船体中心距左墙，单位 m/cm。测量基准为 `base_link` 原点，使用雷达拟合左墙线的垂直距离；不是滚刷间隙，也不是船体到任意最近障碍物的距离。墙观测无效、源时间戳/接收时间过期或遥测过期时显示“无有效观测”，不沿用旧值。

轨迹只显示当前选择的任务，并校验地图和坐标系。遥测过期时隐藏实时目标/导航路径，保留带过期提示的历史轨迹。需要同时升级 App、网关与两个清洗包；新能力通过 `task_stop/task_tracks` 协商。

## 地图与坐标

船头箭头直接使用 TF `map → base_link` 的航向，初始位姿也以 `base_link` 为准。雷达点由网关按扫描时间及雷达 TF 转到 `map`，包含安装平移与旋转；缺少 TF 时不显示该扫描。原 App 的固定 π 航向显示补偿已移除。屏幕/地图转换包含分辨率、地图原点旋转、窗口缩放及 Y 轴翻转。

现场应与 RViz 对照同一点、同一船头方向后验收；软件测试不替代实际安装方向核对。

## 开发验证

```powershell
python main.py --mock
```

Mock 支持建图/保存/列表/预览/选图、初始位姿、模拟稳定窗口、任务开始/暂停/停止/取消、模拟轨迹/墙距和约 8 秒后的完成，始终不连接硬件。它不证明真实定位或清洗效果。

Qt 自动化测试从**仓库根目录**运行（若仍在 `operator_app/`，先 `cd ..`；安装 pytest，Linux 无显示环境设置 `QT_QPA_PLATFORM=offscreen`）。它们不由 `colcon test` 收集：

```bash
python -m pytest operator_app/test -q
```

协议仍为 `f1-operator-v1`，通过 `hello.capabilities` 协商新增能力，建图与选图使用 `mapping/map_catalog`。新版 App 连接旧网关时保留手动界面，禁用新增任务功能。App、网关、定位包及两个清洗包应一起升级；旧客户端不具备新界面的状态门控。
